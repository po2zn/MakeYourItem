# 한 줄 실행

코드창의 연한 화살표 ▷는 한 줄 실행입니다. 이전의 임시 테스트·견적 기능을 대체합니다.

- ▷: 다음 실행 줄을 한 번 실행하고 멈춥니다. 변수, 작업물, 함수 호출 스택, 재귀, import 상태와 난수 상태를 그대로 유지합니다.
- ▶: 새 실행을 시작하거나 멈춘 실행을 이어 끝까지 실행합니다. 기존 실행을 처음부터 반복하지 않습니다.
- ■: 현재 실행을 중단합니다. 이미 소비한 비용과 재료, 등록된 상품은 되돌리지 않습니다. 다시 실행하면 새 변수 상태로 시작합니다.
- 파란 줄은 다음 실행할 줄입니다. 결과 창에도 코드창 이름과 다음 줄 번호를 표시합니다. 가져온 함수 안에서는 해당 모듈 창의 원본 줄을 표시합니다.

두 화살표 모두 실제 실행입니다. 공정 줄을 실행할 때 비용·재료를 소비하고 대장장이 동작을 재생합니다. 동작이 끝나기 전에는 다음 줄을 실행할 수 없습니다. ! 줄에 도달해야 상품을 등록합니다. 계산·대입·출력 줄도 각각 한 번씩 실행하며, 아직 실행하지 않은 줄의 오류나 출력은 미리 발생하지 않습니다.

빈 줄·주석과 선택되지 않은 분기는 건너뜁니다. 조건문은 조건을 평가한 뒤 본문 앞에서 멈춥니다. 반복문은 매 회차의 조건/다음 원소 확인으로 돌아옵니다. 함수 호출 줄에서는 함수 내부로 들어가며 반환 줄을 실행하면 호출한 줄의 나머지 계산·대입을 마칩니다. 함수 정의 줄은 본문을 실행하지 않습니다. 게임 언어의 기존 함수 사전 등록 규칙은 유지합니다.

진행 중에는 한 실행만 유지합니다. 다른 코드창에서 화살표를 눌러도 현재 실행을 이어갑니다. 다른 도면을 새로 시작하려면 먼저 ■로 중단하세요. 실행 도중에는 구매와 판매를 잠급니다. 코드창 내용·이름·목록이 변경되면 다음 진행 시 현재 실행을 중단하며, 다시 눌러야 수정된 코드로 새 실행을 시작합니다. 변경 전에 소비한 비용은 유지됩니다.

실행 한도는 클릭마다 초기화되지 않습니다. 전체 10000명령과 함수 호출 깊이32 제한이 동일하게 적용됩니다. ▷로 시작한 세션은 기본 문법 구조를 해석하되 오류를 해당 문장의 중단 지점으로 보존합니다. 뒤쪽 문법·인자 수·타입·함수 이름·기능 해금 오류로 앞부분의 실행을 차단하지 않습니다. 오류 줄을 실행하는 클릭에서 오류를 표시하고 중단하며, 그 줄의 불완전한 표현식은 실행하지 않습니다. 함수·분기 본문의 오류도 실제로 도달했을 때 처리합니다. 따옴표나 들여쓰기로 토큰 구조를 더 읽을 수 없으면 안전하게 해석된 앞부분만 보존하며 그 이후 소스를 추측해서 실행하지 않습니다.

새로 ▶로 시작한 실행은 기존 전체 검사를 유지합니다. ▷로 시작한 세션에서 ▶를 누르면 그 세션의 도달 시점 검사 방식 그대로 이어갑니다. 오류 창은 실제 오류가 난 코드창의 원본 줄을 표시합니다.

검사: Tools > MakeYourItem > Validate Step Execution.

## 검증 결과

Unity 참조 전체 컴파일, 한 줄 실행13개와 기존 재귀·import·제작·언어·안내서 회귀 검사를 통과했습니다. 별도 Unity Play Mode에서 첫 대입의 무소비, 재료 올리기10G/철1개, 가열2G, ▶ 재개 시 중복 소비 없음, 완료 시 상품1개 등록, 다음 줄 표시, 지연된 오류, 코드 변경 시 중단, 명시적 중단, 모듈·함수 내부 진입 및 이어 실행을 검증했습니다.

로그: Temp/StepChecks.txt, Temp/StepPlayMode.txt. 테스트 에디터의 검색 인덱스 초기화 예외는 제작 코드와 별개로 기록되었습니다. 헤드리스 검사이므로 버튼의 실제 마우스 클릭과 하이라이트 색상·배치는 시각 검증하지 않았습니다.

## 오류를 만날 때 검사하도록 변경

▷ 시작 시 정상 앞부분을 보존하고 문장별 검사 오류를 해당 줄의 실행 지점에 남깁니다. 오류 줄을 실제로 실행하기 전에는 오류 창을 열지 않으며, 이전 공정 비용과 동작을 유지합니다. 문법 오류가 있는 줄의 일부 표현식만 실행하지 않도록 문장 전체를 검사합니다. 잘못된 블록 헤더의 본문은 바깥 실행 범위로 옮겨 실행하지 않습니다.

추가 검증15개와 기존 전체 회귀 검사가 통과했습니다. 별도 Unity Play Mode에서 뒤쪽 인자·괄호 오류가 있어도 앞 공정의10G/철1개와 애니메이션이 반영됨, 오류 줄에서만 진단 표시, 새 ▶의 전체 검사 유지, ▷ 후 ▶의 지연 검사 유지, import 원본 오류 줄 표시를 확인했습니다. 로그: Temp/DeferredChecks.txt, Temp/DeferredPlayMode.txt. 헤드리스 통합 검사이며 오류 창의 시각 배치를 직접 검증한 것은 아닙니다.
