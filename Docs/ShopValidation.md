# 상점 견적·판매 확인 절차

## 연결과 실행

Unity 6000.4.5f1에서 Assets/Scenes/SampleScene.unity를 열고 Play한다. 기존 Forge MVP 오브젝트에 ForgeMvp 스크립트가 연결되어 있으며 별도 프리팹/Inspector 슬롯 연결은 필요 없다. 새 씬이나 상점 오브젝트를 만들지 않는다.

빈 f1 코드 창에 아래 도면을 입력한다. ▷는 시험, ▶는 실제 제작이다. 기존 공용 결과/판매 창이 “공용 결과 / 상점 판매”로 표시된다. 숨겼으면 상단의 판매 창 열기 버튼을 쓰거나 실행 버튼을 누른다. 기본 권장 Game 뷰는1280x720 이상이다.

완성품 목록에서 원하는 ID를 선택하고 아래 견적을 확인한다. 패널 내부를 스크롤하면 긴 실행 기록과 모든 견적 항목을 볼 수 있다. 맨 아래 고정 판매 버튼을 누른다. 판매 후에는 선택이 해제되고 영수증에 지급액이 나온다.

## 기본 도면

```text
Material = 1
Blade = 1(Material)
2(Blade, 7)
3(Blade)
4(Blade, 0)
!Blade
```

## 실제로 확인한 범위

- 런타임 스크립트를 Unity 어셈블리 참조와 함께 C# 컴파일: 성공.
- 에디터 검사 메뉴 코드를 UNITY_EDITOR 정의와 함께 컴파일: 성공.
- Assets/Editor/ForgeEconomyChecks.cs의 실제 Evaluate/ForgeProductionLedger/ForgePricing/ForgeShop 대상 자동 검사14건: 통과.
- 씬 파일의 Forge MVP 오브젝트와 ForgeMvp GUID 연결: 확인. 씬 파일 변경 없음.
- UI 호출 경로: DrawSalesWindow → 선택한 ID → SellProduct → ForgeShop.TrySell. 소스 연결 확인.
- Play Mode 실제 화면·마우스 연타·Craft 코루틴 실행: 미검증. 열려 있는 Unity의 자동 화면 캡처가 두 번 시간 초과하여 UI 입력을 진행하지 않았다.

자동 검사14건은 기본 견적, 추가 가열 견적, 예상/차감 원장 일치, 시험 격리, 뜨거운 완성 실패, 미성형 완성 실패, 타격 실패, 자금 부족, 철 부족, 컴파일 오류, 같은 ID 반복 판매, 다른 ID 선택 판매, 실패 차감의 원자성, 기록 불변성이다. 시험/제작 일치 자동 검사는 평가 이벤트를 실제 차감 원장에 적용하여 비교한 것이며 Unity의 렌더러나 코루틴 대기시간 검증은 아니다.

Unity에서 재실행할 때는 Tools > MakeYourItem > Validate Shop Economy를 누른다. Console에 각 PASS와 TOTAL 14 passed가 나오면 자동 경제 검사가 통과한 것이다. 이 메뉴는 씬 자금·아이템을 바꾸지 않는 격리된 테스트를 실행한다.

## 에디터에서 추가로 확인할 항목

각 독립 사례는 Play를 껐다 켜서 자금100G/철10개/완성품0개로 시작한다.

| 사례 | 실행 방법 | 기대 결과 |
|---|---|---|
| 기본 제작 | 기본 도면을 ▶ 실행, 종료 대기 | 자금88G, 철9개, 완성품1개. 철 검날/성형 완료/열0/공기 냉각, 기본가28, 보너스0, 판매가28, 제작비12, 순이익16, 소비 철1 |
| 시험 격리·일치 | 기본 도면을 ▷ 여러 번 실행 후 ▶ | 시험 동안100G/철10/상품0/작업물 그대로. 예상12/28/16 및 철1. 실제 완료 견적도 동일 |
| 추가 가열 | 2(Blade, 7) 줄을 연속으로 두 번 호출 | 자금86G, 철9, 완성품1. 제작비14, 판매가28, 이익14. 최종 상태는 기본과 같음 |
| 뜨거운 완성 판정 실패 | 4(Blade, 0) 줄을 제거 | ! 줄에서 실패. 자금88G/철9, 새로운 완성품0. 실제 소비12G/철1 표시 |
| 미성형 판정 실패 | Blade=1(1), 4(Blade,0), !Blade만 실행 | 자금90G/철9, 새로운 완성품0 |
| 타격 실패 | 가열7을5로 변경 | 철 올리기+가열만 소비.88G/철9, 상품0 |
| 판매 연타 | 기본 제작 완료 후 판매 버튼 빠르게 반복 클릭 | 자금116G, 상품0. 추가 지급 없음. 선택 해제로 버튼 비활성 |
| 두 상품 선택 | 기본 제작 후 추가 가열 도면 제작. 두 번째 ID를 먼저 선택하여 판매 | 제작 둘 완료 시74G/철8/상품2. 두 번째 판매 후102G/상품1. 첫 번째 비용12 기록 유지. 첫 번째를 새로 선택해 팔면130G/상품0 |
| 다른 창/원문 편집 | 제작 중 새 창 선택·기존 코드 편집 | 시작된 도면 기록·가격은 바뀌지 않음. 제작 중 판매 불가 |
| 패널 표시 | 패널 숨김/열기, 드래그, 스크롤, 확대/축소 | 상품 선택과 견적·판매 버튼을 사용할 수 있고 코드 창 조작을 방해하지 않음 |

이미 상품이 있는 상태에서 다음 도면이 실패해도 기존 상품은 남는다. “완성 실패 시0개”는 실패한 실행이 새 상품을 추가하지 않는다는 의미다.

## 구현 파일과 후속 범위

- Assets/Scripts/ForgeEconomy.cs: 불변 완성품 기록, 실제 차감 원장, 가격 계산/영수증, ID별 판매 목록과 중복 지급 방어.
- Assets/Scripts/ForgeMvp.cs: 실제 상태를 복사한 시험 평가, 실제 Craft 차감/완료 기록, 선택형 상점 UI와 판매 처리.
- Assets/Editor/ForgeEconomyChecks.cs: 반복 실행 가능한 자동 회귀 검사 메뉴.

현재 판매 대상은 철 검날·공기 냉각뿐이다. 물/나무 공정은 추가하지 않았다. 해당 공정 구현 시 성공한 작업물이 획득한 특성을 기록하고 가격 계산에 보너스를 등록해야 한다. 제작비가 늘었다는 이유만으로 판매 보너스를 주지 않는다. 조건·반복문은 현재 미지원이다. 후속 언어 확장에서는 실제 실행된 성공 이벤트만 같은 원장에 넘기면 된다.
