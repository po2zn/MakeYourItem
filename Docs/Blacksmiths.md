# 대장장이와 다이아몬드

대장장이 트리는 기존 테크 트리 상단의 **대장장이** 버튼에서 엽니다. 골드 대신 다이아몬드를 사용합니다. 첫 대장장이는 0번, 공방 좌표는 `(0, 0)`입니다. 번호별 좌표는 `(번호 % 4, 번호 / 4)`의 정수 격자이며 제작 애니메이션 중에도 작업장 좌표는 유지됩니다.

대장장이에 마우스를 올리면 번호, x/y, 호감도, 작업 중/대기 중 상태를 표시합니다. 호감도·위치 함수 구매 전에도 툴팁은 볼 수 있습니다. 화면을 덮은 창 위에서는 뒤쪽 대장장이 툴팁이 나타나지 않으며 마우스 입력을 가로채지 않습니다.

## 고용 및 연구

| 구매 | 비용(다이아) |
|---|---:|
| 1명 → 2명 | 50 |
| 2명 → 3명 | 100 |
| 3명 → 4명 | 300 |
| 4명 → 9명 | 500 |
| 9명 → 16명 | 1000 |
| 호감도 조회 | 25 |
| 위치 조회 | 25 |
| 요구 수량 조회 | 50 |

조회 연구 비용은 이번 구현의 초기 밸런스 값입니다. 고용 비용과 인원은 요청한 값을 사용합니다.

## 함수

대장장이 함수의 숫자·영문 표기는 모두 코드창에서 연파랑으로 표시됩니다. 게임 안 안내서에도 예제가 있습니다.

| 숫자 / 영문 | 사용 |
|---|---|
| `90909` / `smith_demand` | `90909([번호])`: 요구 수량 조회, 연구 필요 |
| `90901` / `smith_gift` | `90901(수량)` 또는 `90901(번호, 수량)`: 선물, 기본 제공 |
| `90902` / `smith_favor` | `90902([번호])`: 호감도 조회, 연구 필요 |
| `90903` / `smith_position` | `90903([번호])`: `(x,y)` 튜플, 연구 필요 |
| `90904` / `smith_run` | `90904(번호, 함수명, 인자...)`: 독립 작업 실행, 기본 제공 |
| `90905` / `smith_count` | `90905()`: 고용 인원 |
| `90906` / `smith_self` | `90906()`: 현재 대장장이 번호 |
| `90907` / `smith_busy` | `90907(번호)`: 작업 중 1, 대기 중 0 |
| `90910` / `giant_rune` | `90910(룬 번호, x, y)`: 거대한 룬 설치 |

`[번호]`는 선택 인자를 뜻하는 문서 표기입니다. 생략하면 현재 코드를 실행하는 대장장이를 대상으로 합니다. 일반 실행은 0번이 담당합니다. 따라서 0번이 조종 코드를 실행 중일 때 `90904(0, ...)`는 작업 중으로 거부됩니다.

```python
333 sword():
    p = 1(1)
    2(p, 7)
    3(p)
    4(p, 0)
    5(p, 2)
    << p

# 총 3명 고용하고 제어문을 연구한 상태
90904(1, sword)
90904(2, sword)
# 두 작업은 병렬 진행. 함수가 반환한 작업물은 자동 제출.
90901(1, 90909(1))
print(90903(1), 90902(1), 90907(1))
```

함수명 뒤에 괄호를 붙이지 않습니다. 추가 인자는 복사해서 전달하며 작업물은 대장장이 간에 공유할 수 없습니다. 각 작업은 시작 시점의 함수·변수 복사본을 사용합니다. 이미 작업 중인 대상은 `-1`, 성공한 명령은 대상 번호를 반환합니다. 각 작업은 별도 세션·공정·애니메이션을 가지며 공용 재고는 공정 시작 시 전부 확인한 뒤 차감합니다. 자원이 부족하면 해당 공정을 차감 없이 중단하고 디버그 창에 알립니다.

## 호감도와 제작 결과

- 호감도 범위: -100~100. 정확한 선물 +5, 틀린 선물 -10. 선물은 1~9개, 실제 전달한 만큼 소비합니다.
- 성공적으로 전달할 때마다 다음 요구 수량을 1~9 중 **직전 수량을 제외하고** 무작위로 정합니다. 자원 부족·잘못된 인자 등으로 전달 자체가 실패하면 바뀌지 않습니다.
- 게임 시간 2시간마다 -1. 하루 -12이며 시간의 나머지는 유지합니다. 현실 시간과 오프라인 시간으로는 감소하지 않습니다.
- 기본 파괴 1%, 대성공 1%, 성공 98%. 음수 호감도에서는 파괴율만 선형 증가하여 -100에서 10%. 양수에서는 대성공률만 증가하여 +100에서 10%. 제작 속도는 바뀌지 않습니다.
- 매 게임 날짜에 기존 대장장이 한 명을 선택합니다. 그날 처음 관측한 시점부터 2게임 시간 동안 불타는 상태이며 대성공률은 50%, 제작 속도는 동일합니다. 주황색 앞치마와 상태 표기로 구분합니다.
- 대성공: 소비한 재료 반환, 같은 완성품 2개, 두 제품에 동일한 무작위 판매 배율 1.25~3.25 적용. 골드는 반환 대상이 아닙니다. 파괴 시 제품을 등록하지 않습니다.
- 고용·호감도·요구 수량·시간 기준·불타는 상태·룬·판매 배율을 저장합니다. 진행 중 코드의 실행 스택은 저장하지 않으며 중단한 작업의 이미 소비한 재료는 반환하지 않습니다.

## 거대한 룬의 초기 기획

룬 각인을 연구한 뒤 기존 룬 번호 1~9와 수정 1개, 등급별 다이아 25/50/75개로 설치합니다. 격자 좌표 0~3에서 자신과 상하좌우 한 칸에 효과를 줍니다. 공방 바닥에 색상 표식으로 나타납니다.

| 계열 | 룬 번호 | 1/2/3등급 효과 |
|---|---|---|
| 대성공 | 1,4,7 | 대성공 +1/2/3%p, 불타는 상태는 50% 유지 |
| 보호 | 2,5,8 | 파괴 -1/2/3%p, 최저 0% |
| 판매 | 3,6,9 | 판매 +5/10/15% |

같은 계열은 범위 안에서 가장 강한 하나만 적용합니다. 같은 위치의 같은 계열은 상위 룬으로 교체할 수 있으며 같거나 낮은 등급으로 중복 소비할 수 없습니다. 이 수치들은 아직 세부 기획이 없던 부분의 초기 제안값입니다.

## 검증

`ForgeBlacksmithChecks.Run()`은 선물, 변경되는 요구 수량, 호감도 경계, 시간 감소, 일일 이벤트, 고용 단계, 룬 범위, 저장 왕복, 구문 색상, 판매 배율, 독립 런타임을 확인합니다.

Play Mode의 `ForgeBlacksmithChecks.StartPlayCheck()`는 저장을 사용하지 않는 별도 공방에서 두 대장장이의 동시 애니메이션·완성품, 중복 명령 거부, 마지막 재료의 원자적 차감, 거대한 룬 구매, 최초 툴팁 좌표, 대성공의 실제 반환 및 2개 생산을 검증합니다. 결과는 `PlayResult`에서 확인합니다.

기존 테크 트리·안내서·확장 제작·캠페인 회귀 검사도 함께 실행했습니다.
