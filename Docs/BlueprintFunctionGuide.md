이 설명서는 플레이어가 코드 창에 작성하는 **도면 언어의 함수**를 다룬다. Unity 내부 C# 메서드의 API 문서는 아니다. [언어 확장 기획서](BlueprintLanguagePlan.md)와 [현재 해석기](../Assets/Scripts/ForgeMvp.cs)를 기준으로 현재 기능과 계획 기능을 구분했다.

## 2. 먼저 알아둘 규칙

### 2.1 숫자의 의미는 위치에 따라 달라진다

```text
Material = 1
Blade = 1(Material)
2(Blade, 7)
```

- 첫 줄의 1은 변수에 저장하는 정수다.
- 두 번째 줄 괄호 앞의 1은 재료 올리기 함수 번호다. Material의 값1은 철 재료 번호로 해석된다.
- 세 번째 줄 괄호 앞의 2는 가열 함수다. 7은 재료 번호가 아니라 목표 열 단계다.
- 함수 번호와 재료 번호는 별개다. 3(Blade)는 물을 쓰는 것이 아니라 타격이다.

위 코드는 설명용 조각이다. 실제 제작 도면에는 마지막에 !Blade가 필요하다.

| 재료 번호 | 의미 | 현재 사용할 수 있는 위치 |
|---|---|---|
| 0 | 공기 | 4(Blade, 0) |
| 1 | 철 | Blade = 1(1) |
| 2 | 나무 | 아직 없음. 향후 장착/연료 후보 |
| 3 | 물 | 아직 없음. 향후 냉각 후보 |
| 4~9 | 특수 재료 후보 | 현재 없음. 숫자로 저장할 수 있어도 공정 투입은 지원하지 않음 |

### 2.2 공통 입력 규칙

현재는 0~2147483647 정수와 변수를 인자로 쓴다. 문자열, 실수, 음수, 계산식, 중첩 호출은 지원하지 않는다. 대입은 재선언 구분 없이 이름 = 값으로 한다. 변수명은 한글/허용 유니코드 문자/밑줄로 시작할 수 있고 뒤에 숫자를 붙일 수 있다. 대소문자는 구분한다.

확장 계획에서는 음수를 포함한 Int32, 계산식, bool, None, 정수 컬렉션을 추가한다. 숫자 공정에는 반드시 요구하는 타입을 전달하며 True를 1처럼 사용하지 않는다. 부동소수점은 계획에도 포함하지 않는다.

**반환값 없음**은 변수에 저장할 값이 없다는 뜻이다. 현재 Result = 2(Blade, 7)은 오류다. 숫자 함수1은 반대로 반환 작업물을 이름에 저장해야 한다. 이름의 철자가 같아야 같은 작업물을 참조한다.

## 3. 현재 사용할 수 있는 공정

<a id="process-1"></a>
### 3.1 재료 올리기 — 1(material)

**상태: 현재 지원.** 철을 소비하고 새 작업물 참조를 돌려준다.

| 항목 | 설명 |
|---|---|
| 호출 형식 | Blade = 1(Material) |
| 입력 | material: 정수, 현재는1(철)만 허용 |
| 반환값 | 새 작업물. 처음에는 열0, 미성형 |
| 비용 | 철 재고1개와 가공 비용10G |
| 사용 조건 | 실제 제작에서 철1개 이상, 자금10G 이상 |
| 보관 방법 | 이름에 대입. 이름은 Blade가 아니라 검날 등으로 바꿔도 됨 |

설명용 예제:

```text
재료 = 1
검날 = 1(재료)
```

| 잘못된 사용 | 이유 |
|---|---|
| 1(1) | 반환 작업물을 변수에 저장하지 않음 |
| Blade = 1(2) | 현재 작업대 재료는 철만 지원 |
| Blade = 1() | 인자1개 필요 |
| Blade = 1(Material)에서 Material을 선언하지 않음 | 미선언 변수 |

반복 호출할 때마다 새 작업물을 만들고 비용을 다시 낸다. 기존 이름에 덮어써도 이전 비용이 환불되지 않는다. 현재는 여러 작업물의 개별 3D 표시가 마련되어 있지 않으므로 기본 도면에서는 하나의 작업물을 이어서 가공한다.

<a id="process-2"></a>
### 3.2 가열 — 2(piece, target)

**상태: 현재 지원.** 작업물의 열 단계를 target으로 설정한다.

| 항목 | 설명 |
|---|---|
| 입력1 | piece: 1 함수에서 받은 작업물 |
| 입력2 | target: 정수1~9 |
| 반환값 | 없음 |
| 비용 | 호출할 때마다2G |
| 상태 변화 | 열 단계가 target이 됨. 기존 성형 여부는 유지 |
| 일반 사용 | 타격 전에6~9로 설정 |

설명용 예제:

```text
Blade = 1(1)
2(Blade, 7)
```

열0에서7로 바꾸며 “7만큼 더하기”가 아니다. 현재 코드는 이미 열7인 작업물에 다시7을 지정해도2G를 소비한다. 현재는 낮은 목표를 지정해도 그 값으로 설정되므로 2(Blade, 6)은 열9를6으로 바꿀 수도 있다. 이 동작을 물리적인 냉각이나 무료 온도 조절로 오해하지 않는다.

| 잘못된 사용 | 이유 |
|---|---|
| 2(Blade, 0), 2(Blade, 10) | 허용 열 단계1~9 밖 |
| 2(1, 7) | 첫 인자가 작업물이 아님 |
| Result = 2(Blade, 7) | 반환값 없음 |
| 2(Blade) | 인자2개 필요 |
| 2(Blade, 6 + 1) | 현재는 계산식 미지원. 확장 후 허용 예정 |

열 단계는 게임의0~9 상태값이며 섭씨7°C라는 뜻이 아니다.

<a id="process-3"></a>
### 3.3 타격 — 3(piece)

**상태: 현재 지원.** 충분히 가열된 작업물을 검날 모양으로 성형한다.

| 항목 | 설명 |
|---|---|
| 입력 | piece: 작업물1개 |
| 반환값 | 없음 |
| 비용 | 추가0G |
| 필요 상태 | 열 단계6 이상 |
| 상태 변화 | 성형 완료. 열 단계는 유지 |

설명용 예제:

```text
Blade = 1(1)
2(Blade, 7)
3(Blade)
```

| 잘못된 사용 | 이유 |
|---|---|
| 새 작업물을 바로 3(Blade)로 타격 | 초기 열0, 타격 조건 미달 |
| 2(Blade, 5) 다음에 3(Blade) | 열5는 기준6 미만 |
| 3(1) | 작업물이 아님 |
| Result = 3(Blade) | 반환값 없음 |

현재는 뜨거운 성형 완료 검날을 다시 타격해도 별도 경도나 판매 보너스가 생기지 않는다. 낮은 열에서 실패하면 앞서 성공한 재료 올리기와 가열 비용은 남는다.

<a id="process-4"></a>
### 3.4 냉각 — 4(piece, coolant)

**상태: 현재 지원은 공기(0)뿐이다.** 작업물의 열을0으로 만든다.

| 항목 | 설명 |
|---|---|
| 입력1 | piece: 작업물 |
| 입력2 | coolant: 정수, 현재0만 허용 |
| 반환값 | 없음 |
| 비용 | 공기 냉각0G |
| 상태 변화 | 열0. 성형 여부는 유지 |
| 일반 사용 | 타격을 마친 뒤 완성품 판정 전에 호출 |

설명용 예제:

```text
Blade = 1(1)
2(Blade, 7)
3(Blade)
4(Blade, 0)
```

공기 냉각은 미성형 작업물에도 호출할 수 있지만, 냉각만으로 성형되지 않는다. 타격 전에 식혔다면 다시 가열해야 타격할 수 있다.

| 잘못된 사용 | 이유 |
|---|---|
| 4(Blade, 3) | 물 냉각은 현재 미지원 |
| 4(Blade, 2) | 나무는 현재 냉각 재료로 사용할 수 없음 |
| 4(1, 0) | 작업물이 아님 |
| Result = 4(Blade, 0) | 반환값 없음 |

향후 물 냉각은 뜨거운 검날에 담금질 효과를 주고, 식은 검날에는 물값만 들 수 있는 방향이다. **지금은 물에 의한 경도 변화·보너스·경고가 구현되어 있지 않다.**

<a id="finish"></a>
### 3.5 완성품 판정 — !piece

**상태: 현재 지원. 함수가 아니라 완성품 판정 문장이다.**

| 항목 | 설명 |
|---|---|
| 문법 | !Blade |
| 대상 | 성형 완료이며 열0인 작업물 |
| 결과 | 실제 제작에서는 완성품1개를 판매 대기 재고에 추가 |
| 추가 비용 | 0G |
| 판매 | 자동으로 팔리지 않음. 공용 판매 창에서 판매 |
| 이후 문장 | 명령을 더 쓰면 오류. 빈 줄/주석만 허용 |

| 잘못된 사용 | 이유 |
|---|---|
| !Blade에서 Blade를 선언하지 않음 | 미선언 변수 |
| !Material에서 Material = 1 | 정수이며 작업물이 아님 |
| 가열·성형 없이 바로 반환 | 성형 미완료 |
| 타격 뒤 식히지 않고 반환 | 열0이 아님 |
| !Blade 다음 줄에 2(Blade, 7) | 완성품 반환 이후 명령 금지 |

확장 계획에서는 모듈 본문 및 그 if/else 안에만 !를 쓸 수 있다. def/for/while 안에서는 금지한다. return은 함수 값을 돌려줄 뿐 완성품을 등록하지 않는다.

## 4. 지금 실행할 수 있는 완성 도면

아래 예제 전체를 빈 코드 창에 넣는다.

```text
Material = 1          # 철 재료 번호
Blade = 1(Material)  # 철1개와10G 사용
2(Blade, 7)          # 목표 열7, 연료2G
3(Blade)             # 검날 성형
4(Blade, 0)          # 공기 냉각
!Blade               # 완성품 검사
```

▷ 시험 실행은 실제 자원·판매 재고·작업물을 바꾸지 않고 결과와 예상 비용을 보여 준다. ▶ 실제 실행은 공정을 진행하고 자원을 차감한다. 실행 중 중복 실행과 판매는 잠긴다.

| 항목 | 정상 결과 |
|---|---|
| 사용 자원 | 철1개, 12G |
| 완성품 | 공기로 식힌 철 검날1개 |
| 판매가 / 이익 | 28G / 16G |
| 초기100G·철10개에서 제작 후 | 88G·철9개·완성품1개 |
| 이어서 판매 후 | 116G·철9개·완성품0개 |

현재 시험은 시작 자금·철의 복사본으로 자원 부족까지 확인하며 실제 자원은 바꾸지 않는다. 실제 실행도 각 공정 직전에 자원을 확인하고, 실패 전 성공한 공정의 비용만 유지한다. 현재 각 평가 Step에0.65초 대기가 붙으며, PDF의 제작 시간 예시와 일치하는 기능은 아직 아니다.

## 5. 확장 계획의 조회·계산 함수

**이 절의 모든 함수와 예제는 아직 미구현이다.** 별도 표시 없는 짧은 코드는 사용법을 보여 주는 조각이며 단독 완성 도면이 아니다. 계산 함수 자체는 재료·G를 소비하지 않는다.

<a id="heat"></a>
### 5.1 heat(piece) — 열 단계 읽기

- 입력: 현재 실행에서 생성된 작업물1개.
- 반환: 현재 열 단계0~9 정수.
- 변화: 작업물·비용·시간을 바꾸지 않는다.
- 용도: 가열이 필요한지 또는 타격 가능한지 판단한다.

```text
Blade = 1(1)
Current = heat(Blade)  # 0
2(Blade, 7)
Current = heat(Blade)  # 7
```

오류: heat(), heat(1), heat(None), 다른 실행의 작업물 참조. 함수의 인자 위치에서 오류를 알린다. 화면 색상이나 실제로 지난 시간을 읽는 기능이 아니다. 자연 냉각은 없으므로 heat만 계속 읽어도 작업물이 식지 않는다.

<a id="abs"></a>
### 5.2 abs(n) — 절댓값

- 입력: signed Int32 정수1개.
- 반환: 부호를 제거한 정수. abs(-2)는2, abs(2)도2.
- 용도: 목표와 실제 열 단계의 차이를 계산한다.

```text
Actual = 5
Target = 7
Difference = abs(Actual - Target)  # 2
```

오류: abs(), abs(1, 2), abs(True), abs(Blade). abs(-2147483648)은 양수 결과가 Int32 범위를 넘으므로 범위 오류다. 정수 범위를 벗어나도 자동으로 음수로 돌아가지 않는다.

기존 설계의 숫자10 절댓값 후보 대신 abs를 사용한다. 10(-2)는 현재도 확장안에서도 절댓값 함수가 아니다.

<a id="len"></a>
### 5.3 len(values) — 원소 개수

- 입력: 리스트·딕셔너리·집합·튜플 중 하나.
- 반환: 0 이상의 정수.
- 딕셔너리는 키의 개수, 집합은 중복을 제거한 원소 개수를 센다.

```text
CandidateCount = len([9, 7, 5])  # 3
MaterialKinds = len({1: 2, 3: 1})  # 2
AllowedCount = len({0, 0, 3})  # 2
LimitCount = len((6, 9))  # 2
EmptyCount = len([])  # 0
```

오류: len(7), len(None), len(Blade), len(), len([1], [2]). 문자열은 첫 확장 버전의 자료형이 아니므로 문자열 길이 기능도 없다. 단계별 구현 중에는 먼저 리스트를 지원하고, 컬렉션 확장 단계에서 나머지를 추가한다.

<a id="min"></a>
### 5.4 min(values) — 최솟값

- 입력: 비어 있지 않은 정수 리스트 또는 정수 튜플1개.
- 반환: 가장 작은 원소. 원본의 순서를 바꾸지 않는다.
- 용도: 여러 열 후보 중 최저값 또는 목표의 상한을 정한다.

```text
Lowest = min([9, 7, 5])  # 5
Target = min([10, 9])  # 9
```

오류: min([]), min(()), min(1, 2), min({1, 2}), min({1: 2}), min([1, True]). 두 숫자도 min([a, b])로 묶어 전달한다. “목록의 첫 번째 적합값 찾기”와 다르다. [9,7,5]의 min은5이며 제한7 이하의 첫 후보는7이다.

<a id="max"></a>
### 5.5 max(values) — 최댓값

- 입력: 비어 있지 않은 정수 리스트 또는 정수 튜플1개.
- 반환: 가장 큰 원소. 원본은 변경하지 않는다.
- 용도: 타격 기준보다 목표가 낮아지지 않도록 하한을 정한다.

```text
Highest = max([9, 7, 5])  # 9
Target = max([4, 6])  # 6
Limits = (6, 9)
Clamped = min([Limits[1], max([Limits[0], 10])])  # 9
```

오류: max([]), max(()), max(1, 2), max({1, 2}), max(None). 위 중첩 호출은 확장안에서 허용하지만 현재 해석기는 지원하지 않는다.

<a id="random"></a>
### 5.6 random(low, high) — 정수 추첨

- 입력: 정수 하한 low, 정수 상한 high의2개 인자. low <= high여야 한다.
- 반환: low 이상 high 이하의 정수. **양쪽 경계를 모두 포함한다.**
- 용도: 열 후보를 추첨하거나 확률 조건을 만든다.

```text
Candidate = random(1, 7)  # 1, 2, 3, 4, 5, 6, 7 중 하나
Fixed = random(7, 7)  # 항상7
Chance = random(1, 100) <= 25  # bool 조건
```

오류: random(), random(7), random(7, 1), random(True, 7), random(1, 7, 9). 인자 없는 random()이나 실수 난수는 지원하지 않는 안이다. 확률 예시는 조건을 만들 뿐 자동으로 보너스나 저주를 적용하지 않는다.

계획된 시험/실제 규칙:

1. 같은 소스·초기 공방 상태·시드·규칙 버전에서 같은 결과를 낸다.
2. 같은 제작 시도에서 시험만 반복하면 같은 난수열이다. 시험은 실제 난수 상태와 자원을 바꾸지 않는다.
3. 실제 제작의 첫 공정이 성공하면 해당 시도를 소비한다. 이후 실패해도 다음 제작 시도는 새 시드다.
4. 공정 없이 건너뛰거나 컴파일에 실패하면 시드가 바뀌지 않는다. 원문 변경만으로 새 시드를 뽑지 않는다.
5. 다른 제작/판매로 초기 자원이 달라지면 이전 시험 결과는 무효화된다. 실제 실행은 현재 상태로 재평가한다.

random(1,7)의7 툴팁은 “난수 범위의 최댓값 · 7 포함”이며 2(Blade,7)의 “목표 열 단계”와 다르다. 아직 미구현인 정책이며 현재 게임에는 난수 실행이 없다.

<a id="set"></a>
### 5.7 set() — 빈 집합

- 입력: 없음.
- 반환: 빈 정수 집합.
- 용도: 원소가 없는 허용 재료 묶음을 표현한다.

```text
Allowed = set()
Count = len(Allowed)  # 0
Allowed = {0, 0, 3}
Count = len(Allowed)  # 2
CanUseAir = 0 in Allowed  # True
```

{}는 빈 딕셔너리다. 빈 집합으로 사용하려면 set()을 써야 한다. set([0,3]) 같은 변환 인자는 첫 버전에서 받지 않는다. 집합은 순서·인덱스가 없고 중복을 제거한다. add/remove 메서드는 계획에 없으며 위처럼 전체 변수를 재대입한다.

Allowed에 물3이 들어 있어도 물 냉각 공정이 실행 가능해지는 것은 아니다.

<a id="user-functions"></a>
## 6. 사용자 함수 만들기 — def와 return

**상태: 확장 계획.** 자주 사용하는 계산이나 공정을 이름으로 묶는다. def와 return은 함수가 아니라 함수를 정의하고 끝내는 문법이다.

### 6.1 정의·호출·반환

```text
def difference(actual, target):
    result = abs(actual - target)
    return result

Gap = difference(5, 7)  # 2
```

| 항목 | 사용 규칙 |
|---|---|
| 정의 | 최상위에서 def 이름(매개변수): 뒤에 공백4칸으로 본문 작성 |
| 매개변수 | 위치 인자 최대8개. 기본값·키워드 인자·가변 인자는 제외 |
| 지역 변수 | 함수 안의 result 등은 함수 안에서만 사용. 모듈 값이 필요하면 인자로 전달 |
| 반환 | return 값. return만 쓰거나 끝에 도달하면 None |
| 정의 순서 | 소스 전체에서 함수를 수집하므로 정의보다 앞에서 호출 가능 |
| 범위 | 같은 코드 창 소스의 함수만 호출. 창 제목 f1은 자동 함수 정의가 아님 |
| 이름 | 기존 변수명 규칙 사용. 내장 함수 이름을 사용자 def로 재정의할 수 없음 |
| 재귀 | 직접/간접 재귀 미지원. 일반 호출도 깊이32 제한 |

함수 이름 difference, choose_heat, heat_to는 이 설명서의 예제 이름이며 내장 함수가 아니다. 사용하려면 해당 def를 같은 도면에 작성해야 한다.

오류 예: difference(5)는 인자 수 부족, 최상위 return 7은 함수 밖 return, 함수 밖에서 result를 읽으면 미정의 변수, def abs(n):은 내장 함수 재정의, f가 f 자신을 호출하거나 f→g→f로 돌아오면 재귀 오류다.

확장안은 값 이름과 호출 이름을 구분한다. abs = 1처럼 기존 변수명을 써도 abs(-2) 호출은 내장 함수를 가리킨다. 다만 읽기 쉬운 도면을 위해 다른 변수명을 사용하는 편이 좋다.

### 6.2 공정을 묶는 함수

확장 계획의 **완성 도면**:

```text
def heat_to(piece, target):
    2(piece, target)
    return heat(piece)

Blade = 1(1)
Actual = heat_to(Blade, 7)
3(Blade)
4(Blade, 0)
!Blade
```

가열은1회, Actual은7이며 기본 제작비는12G다. 함수에 넘긴 작업물은 같은 참조이므로 가열 상태가 호출자에게도 보인다. 내부 공정 비용은 일반 호출과 동일하게 차감된다.

공정을 포함하는 사용자 함수는 독립 호출문 또는 이름 대입의 우변 전체에서만 호출한다. Actual = heat_to(Blade,7)은 허용하지만 if heat_to(Blade,7) > 0:이나 abs(heat_to(Blade,7))는 오류다. 먼저 별도 줄에서 실행해 비용 발생 지점을 보이게 한다. 순수 계산 함수 difference는 계산식 안에서 호출할 수 있다.

함수 안에서 !piece를 쓰지 않는다. 작업물을 반환하고 바깥에서 판정한다. 컬렉션은 작업물과 달리 값 복사이므로 함수에서 바꾼 목록을 호출자가 쓰려면 return하여 다시 대입한다.

### 6.3 첫 적합 후보를 고르는 함수

확장 계획의 **완성 도면**:

```text
def choose_heat(candidates, limit):
    selected = None
    for candidate in candidates:
        if candidate <= limit:
            selected = candidate
            break
    return selected

Target = choose_heat([9, 7, 5], 7)
if Target != None:
    if Target >= 6 and Target <= 9:
        Blade = 1(1)
        2(Blade, Target)
        3(Blade)
        4(Blade, 0)
        !Blade
```

9를 건너뛰고7을 선택한 뒤 break로 종료한다.5는 검사하지 않는다. 후보를 고르는 반복에는 가열이 없으므로 실제 가열은 한 번이다. [9,8] 또는 []를 넘기면 None이 돌아오고 철을 올리기 전 건너뛴다. [5,7]이면 첫 적합값5를 반환하나 타격 조건 검사에서 제작을 건너뛴다. 함수가 자동으로 두 번째 후보를 다시 선택하지는 않는다.

## 7. 함수와 함께 사용하는 문법 빠른 참조

**이 절은 확장 계획이며 현재는 실행되지 않는다.** 아래 항목은 함수 호출과 혼동하지 않도록 함께 정리했다.

### 7.1 제어문

| 문법 | 역할 | 주의 사항 |
|---|---|---|
| if 조건: / else: | 조건에 맞는 한 블록 실행 | 조건은 bool. if 1: 금지. 블록은4칸 들여쓰기 |
| for x in values: | 리스트/튜플의 원소를 순서대로 순회 | 진입 시 스냅샷 사용. 집합/딕셔너리 순회는 첫 버전 제외 |
| while 조건: | 매회 조건을 검사하며 반복 | 상태를 바꾸지 않으면 끝나지 않을 수 있음 |
| break | 가장 가까운 현재 함수의 반복 종료 | 함수 호출자의 반복을 대신 종료하지 못함 |
| return 값 | 현재 함수 종료 및 값 전달 | 판매 완료가 아니며 최상위에서는 금지 |
| in | 원소/키 포함 여부 검사 | 리스트·튜플·집합은 원소, 딕셔너리는 키 |

비교는 == != < <= > >=, 논리는 and/or/not을 사용한다. and/or는 앞에서 결과가 정해지면 뒤를 평가하지 않는다. 산술은 + - * // %이며 /, 문자열, 실수는 제외한다. 일반 정수의0 나누기와 범위 초과는 오류다. Python 전체 문법을 지원하는 것은 아니다.

### 7.2 자료구조

| 자료구조 | 만들기·읽기 | 첫 버전 변경 | 주의 사항 |
|---|---|---|---|
| 리스트 | Values = [9,7,5], Values[0] | Values[0] = 7 | 순서 유지. 음수 인덱스/범위 밖 접근/append/슬라이스 제외 |
| 딕셔너리 | Stock = {1:2,3:1}, Stock[1] | Stock[1] = Stock[1] - 1, 새 키 대입 | 없는 키는 오류. in으로 먼저 확인. 실제 재고와 별개 |
| 집합 | Allowed = {0,3}, 빈 값 set() | 변수 전체 재대입 | 중복 제거, 인덱스/원소 추가·삭제 메서드 없음 |
| 튜플 | Limits = (6,9), Limits[0] | 변경 불가 | 한 원소는 (7,), 빈 값은 (). (7)은 정수 괄호식 |

원소 및 딕셔너리 키/값은 정수만 허용한다. 중첩 컬렉션·작업물·bool 원소는 제외한다. 각 컬렉션은 최대1,024개 원소다. 리스트/딕셔너리/집합/튜플은 대입·함수 인자·반환 시 값 의미로 복사하며 작업물만 공유 참조다.

| 타격 전에6 이상 가열 필요 | 가열이 타격보다 앞인지, 중간에 냉각했는지 확인 |
| 완성품 검사 실패 | 타격을 마쳤는지, 마지막 열이0인지 확인 |
| 반환값이 없습니다 | 2~4 호출 앞의 Result = 제거 |
| 완성품 반환이 필요합니다 | 완성 도면 끝의 !Blade 확인 |
| 확장 계획의 없는 딕셔너리 키 | 읽기 전에 key in Stock 검사 |
| 확장 계획의 반복/호출 한도 초과 | 조건 변화와 break, 호출 체인 확인 |

컴파일 오류는 실제 제작 시작 전에 멈춘다. 공정 오류/자원 부족으로 중간에 멈추면 이전 성공 공정의 비용은 환불되지 않으며 실패 공정 자체의 재료는 차감하지 않는다. 시험 결과와 실제 소모를 구별해서 확인한다.

확장 계획의 한도는 실행10,000단위, 사용자 호출 깊이32, 프레임당256단위다. 한도를 넘을 다음 명령/호출 줄에서 멈추며, 실제 실행은 그 전 성공 공정의 비용을 유지한다. 공정이0개이고 조건 때문에 완성품 판정에 도달하지 않은 경우에는 비용 없이 건너뛴다는 규칙도 확장 때 추가할 예정이다. 현재 해석기에는 이 조건부 건너뜀이나 실행 제한이 없다.

## print 문자열 출력과 독립 디버그 창

사용 예:

~~~text
print("안녕하세요")
Message = "제작을 시작합니다"
print(Message)
~~~

문자열 인자1개를 받아 디버그 창에 출력하고 None을 반환한다. 작은따옴표/큰따옴표, 빈 문자열, 문자열 변수와 기존 이스케이프를 지원한다. print() / print(1) / print("a", "b")는 인자 오류다. 숫자 별칭은 지정하지 않았으며 기존16개 숫자 대응에 영문 내장 함수print가 추가되어 공통 데이터 항목은17개다. print는 다른 함수와 같은 연노랑색이며 문자열 인자/반환값 설명 툴팁을 제공한다.

출력 전용 코드는 ! 없이 실행할 수 있다. 제작 공정을 포함한 코드의 ! 요구는 유지한다. 컴파일 실패 시 출력은 실행되지 않는다. 실행 중 실패하면 이전 성공 출력만 남는다. 조건·반복·사용자 함수 안에서 실제로 실행된 호출만 출력하고, 실제 제작은 공정 Step 사이의 출력 Step을 순서대로 재생한다. 출력은 비용/재료 소비/공정 애니메이션 지연/상품 생성/난수 시드 소비를 추가하지 않는다. print 전용 실행은 상점 결과를 변경하지 않는다. 시험은 같은 실행기의 출력만 미리 보여주며 실제 재고/자금을 변경하지 않는다.

첫 출력 시 별도 ‘디버그 출력’ 창이 열리며 도면 이름과 시험/실제 실행 구분 뒤에 메시지가 누적된다. 상단 ‘디버그 창’ 버튼으로 다시 열거나 숨길 수 있다. 제목 드래그 이동, 좌우·아래 크기 조절(최소320×160), 내부 스크롤, 새 출력 따라가기, ‘지우기’와 닫기를 제공한다. 이 창은 화면 좌표의 독립 읽기 전용 출력 창이며 작업 공간 확대와 분리된다. 출력 창 위 마우스 입력은 뒤 코드 창/상점/작업 공간에 전달하지 않는다. richText=false이므로 출력 문자열의 <color> 등은 태그로 실행되지 않는다.

안전한 출력 범위: 실행당 최대256회/65536문자이며 초과 호출 줄에서 실행 오류가 난다. 창은 최근256항목/65536문자 이내만 보관하고 오래된 내용을 지운다. 출력 기록은 세션 중에만 유지한다.

주요 파일: BlueprintAliases(Print 등록/서명), BlueprintValidator(문자열 검사/출력 전용 판정), BlueprintRuntime.Call(출력 Step), ForgeMvp.Execute/Craft/DrawDebugWindow/DrawDebugContents(시험·실제 출력과 창), ForgeDebugOutput(누적 버퍼), BlueprintPrintChecks(9개 새 검사).

검증: Unity 참조 및 ENABLE_INPUT_SYSTEM/UNITY_EDITOR C# 컴파일 통과. standalone Mono에서 print9+기존56=65개 검사 통과. 한글/빈 문자열/이스케이프, 함수·조건·반복, 공정 사이 출력 순서, 기존12G 제작비/28G 판매가, 시험 결과 일치, 잘못된 인자, 실패 이전 출력 유지, ! 규칙, 색상/툴팁, 출력 한도/버퍼 지우기를 확인했다. Temp/BlueprintPrintChecks.txt에 결과를 기록했다. Unity 창 캡처가 두 번 window capture timed out으로 실패하여 Play Mode 버튼 클릭/출력 창 레이아웃·이동·리사이즈는 직접 확인하지 못했다.

직접 확인: SampleScene Play → 코드 창에 위 예제 입력 → ▷/▶ 실행 → 디버그 창의 출력 순서와 시험/실제 표기 확인. 창을 이동/좌우·아래 리사이즈하고 지우기/닫기/상단 버튼 재열기를 확인한다. 기본 제작 도면의 각 공정 사이에 print("가열 후") 등을 넣어 실제 제작 애니메이션과 출력 순서를 확인한다. Tools > MakeYourItem > Validate Print Output으로 출력 검사를 재실행할 수 있다.

## 조건·반복문 변수의 실행 시점 검사

변수 읽기를 ‘모든 정적 경로에서 미리 대입되어야 함’ 검사에서 실제 실행 시점 검사로 변경했다. BlueprintValidator.ExprCore는 변수 참조의 타입을 Unknown으로 두어 이전 회차/선택 분기에서 생성되거나 타입이 바뀐 변수를 차단하지 않는다. 문법, 식별자 형식, 함수 존재/인자 수, 리터럴에서 확정할 수 있는 타입, 잘못된 break/return 및 실행 한도 검사는 유지한다.

BlueprintRuntime.Block은 원래부터 if/elif/else와 for/while 본문에 동일한 환경 딕셔너리를 전달한다. 실행된 대입은 다음 회차와 블록 밖에서 보이며, 존재하지 않는 이름을 Eval에서 실제로 읽으면 그 원본 줄에서 ‘변수 '이름'에 아직 값이 없습니다. 이 줄 실행 전에 값을 대입하세요.’ 실행 오류가 발생한다. 실행하지 않은 분기나 단락 평가로 건너뛴 피연산자의 미정의 변수는 오류가 아니다. 반복0회면 새 변수가 생기지 않는다. 함수의 기존 지역 환경과 호출 간 분리는 유지하며 Python 전체 글로벌 이름 탐색을 추가한 것은 아니다.

이전3(Missing) 사례는 이제 컴파일 오류가 아니라 해당 호출 줄의 실행 오류다. 이미 성공한 철 올리기/가열의12G와 철1개는 기존 제작 실패 규칙대로 남고 완성품은 등록되지 않는다. 시험 실행은 여전히 실제 자원을 변경하지 않는다. 컴파일 오류 무소비 회귀 검사는 명백한 잘못된 인자 수3(Blade,1)로 유지하고, 미정의 변수의 실행 중 실패는 별도 회귀 검사로 확인한다.

확인: 사용자가 제공한 a=1 → while(True) → 첫 회차res 생성 → 후속 회차 가열/타격/냉각 → break → !res 도면을 그대로 실행해 철1개/제작비12G/판매가28G/순이익16G 확인. 영문 대응, 분기 밖 사용, for 변수의 블록 밖 사용, 실행하지 않은 분기, 반복0회, 선사용 후대입, None에서 작업물로 재대입, 함수 지역 변수와 호출 격리, 실패 전 비용 유지도 확인했다. Unity 참조 C# 컴파일 및 standalone Mono 변수12+기존65=77개 검사 통과. 실제 Play Mode UI 조작 검증은 미수행이다. Tools > MakeYourItem > Validate Runtime Variables로 새12개 검사를 실행할 수 있다. 결과: Temp/BlueprintVariableChecks.txt.
