범위: 원인 조사만 수행. 게임 소스/씬/Packages/ProjectSettings는 수정하지 않음.
Unity 6000.4.5f1, Editor Play Mode, 1920x1080 Game View.
저장 슬롯을 불러온 뒤 이번 실행의 activeSaveSlot을 0으로 바꾸고 시간을 정지하여
테스트 조작의 저장을 차단함. 주석 100줄과 창 배치는 메모리에서만 변경함.

확인된 재현 조건 (동일 조건 2회):
1. 긴 코드가 있는 코드창과 도면 안내서를 겹친다.
2. 코드창 오른쪽 세로 스크롤바 손잡이를 누른다.
3. 커서를 코드창 밖, 안내서 본문으로 옮겨 버튼을 놓는다.
4. 빈 배경에서 드래그를 시도한다. 화면이 이동하지 않는다.

관찰:
- 정상 상태 hotControl=0.
- 위 동작 직후 hotControl=1872가 남음. dragButton=-1, codePointerControl=0,
  edge=-1, guideBook.Dragging=false. 즉 자체 입력 소유 상태는 모두 비활성임.
- 재현 반복에서도 동일한 hotControl 값이 남음.
- 배경 드래그 후 workspaceOffset=(0,0)으로 유지되어 이동 실패 확인.
- 이 상태에서도 코드창 휠 입력은 scroll.y=0 -> 240으로 정상 작동함.
- ESC 메뉴를 열면 hotControl=0. 닫고 동일한 배경 드래그를 실행하면
  workspaceOffset=(0,0) -> (60,75)로 이동함.
- 테크 트리 전환 버튼은 작동했고, 전환 과정의 캡처 초기화로도 복구됨.
  모든 클릭이 영구적으로 막히는 증상이라고 일반화하지 말 것.

원인:
ForgeMvp.WorkspacePointerActive는 dragButton, edge, codePointerControl만 확인한다.
DrawEditorScrollbars의 GUI.VerticalSlider/HorizontalSlider가 잡은 네이티브
마우스 캡처는 이 판정에 포함되지 않는다.
따라서 스크롤바를 잡은 동안에도 DrawGuideBookBehindWindows에서 안내서 입력이
차단되지 않는다. 커서가 안내서에 들어가면 ForgeBookWindow.Draw 마지막의
Event.Use가 MouseDrag/MouseUp을 소비한다. 스크롤바가 해제 이벤트를 받지 못해
hotControl이 남고, 배경 드래그 시작 조건 hotControl==0을 만족하지 못한다.

수정 방향 (이번 조사에서는 미적용):
- 스크롤바를 포함한 네이티브 입력 소유자를 추적한다.
- 포인터를 잡은 컨트롤에 Drag/MouseUp을 우선 전달하고 다른 창은 이를 소비하지 않는다.
- MouseUp 이후 남은 캡처/드래그 상태를 소유자 기준으로 정리한다.
- 디버그/판매창/툴바 등 같은 pointerOwned 판정을 쓰는 영역도 회귀 검증한다.
- 모든 MouseUp 이전에 hotControl을 무조건 0으로 만드는 방식은 버튼/텍스트 선택의
  정상 해제를 방해할 수 있으므로 피한다.

검증 범위 및 한계:
배경 팬/휠, 안내서 이동/크기 변경/본문 휠, 코드창 이동/선택 드래그,
테크 트리 팬/휠/왕복, Game View 경계를 넘는 드래그를 실제 마우스로 시험함.
재현된 문제는 네이티브 스크롤바의 캡처 잔류 및 이후 배경 드래그 실패임.
휠 자체가 완전히 멈추는 별도 조건은 이번 시험에서 확정하지 못함.
드래그 상태 잔류 시 휠이 차단되는 코드 조건은 존재하지만 실제 발생 증거와 구별해야 함.
임시 우회: ESC를 두 번 눌러 메뉴를 열었다 닫으면 확인된 캡처 잔류는 해제됨.
