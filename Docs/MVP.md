# 첫 구현 범위

설계 근거: GameDesign.pdf 2장 플레이 화면, 3장 숫자 언어, 4장 오류 처리, 7장 구현 우선순위.

## 실행
Unity 6000.4.5f1에서 Assets/Scenes/SampleScene.unity를 열고 Play.
씬의 Forge MVP 오브젝트에 ForgeMvp 컴포넌트를 연결했다. 누락 시 SampleScene에서만 런타임 생성하는 보조 경로도 유지한다.
기존 게임 UI가 없는 기본 프로젝트이므로 임시 IMGUI를 사용한다.
코드 편집창, 시험/실제 실행, 콘솔, 판매 버튼과 큐브 작업물을 제공한다.

## 언어와 규칙
영문 대소문자 구분 변수, 0 이상 Int32 정수, 대입/참조, 숫자 함수 1~4, !작업물.
1(1)은 철을 올려 작업물을 반환한다. 반환값 저장 필수.
2(작업물, 열)은 열 단계 1~9와 연료 2G.
3(작업물)은 열 6 이상에서 검날 성형.
4(작업물, 0)은 무료 공기 냉각.
!작업물은 성형 및 열 0을 검사한다. 반환 뒤 명령은 거부한다.
빈 줄은 허용하며 줄 번호를 보존한다. 중첩 호출, 음수와 조건식은 미지원. #부터 해당 줄 끝까지는 주석이며 실행에서 제외한다.
구조/변수/타입 검사를 전체 소스에 먼저 실행하고 별도 상태에서 공정 평가한다.
실제 제작은 평가된 성공 공정을 순서대로 재생한다. 공정 실패 이전 소비는 남는다.
시험은 별도 평가 결과만 표시하며 실제 자금/철/작업물/판매 재고를 변경하지 않는다.
실행 중에는 두 실행 버튼을 잠그며, 입력을 변경해도 시작된 실행 스냅샷은 유지한다.

## 임시 경제
시작 자금 100G, 철 재고 10개. 철 올리기는 철 1개와 가공 비용 10G.
가열 2G, 공기 0G, 기본 검날 판매 28G. 기본 총 비용 12G, 이익 16G.
재고는 이미 보유한 원재료이며 10G는 올리기 시 발생하는 비용으로 임시 정의한다.
공정마다 0.65초 대기. 판매 재고는 누적되고 버튼 1회에 1개 판매.
저장/로드, 철 재구매, 실패 작업물 재개/회수는 미구현.

## 에디터
여러 줄 TextArea의 기본 선택, 복사/붙여넣기와 가로/세로 ScrollView.
네 가장자리 8px 영역에서 크기 조절, 반대편 고정. 최소 340x180 (작은 화면에서는 화면 크기 우선).
창은 작업 공간 좌표에 놓이며 화면 밖으로 이동/확장할 수 있다. 가장자리에는 방향 표시 상자가 나온다.
숫자 전체 토큰의 렌더링 위치를 GUIStyle로 계산한다.
0.5초 호버 후 함수/인자 위치/정수 설명. 입력/스크롤/리사이즈와 포인터 이동은 대기를 재설정한다.
줄별 독립적인 부분 구문 분석이므로 다른 줄이 미완성이어도 툴팁은 동작한다.

## 후속 우선순위
1. 물 담금질의 상태별 경도·수익 비교와 나무 손잡이.
2. 조건문/온도 조회, 상점, 가속, 자동판매.
3. 특수 재료 4~9, 행운/저주/엔딩.
4. 정식 토큰/AST/바이트코드 분리, 실행 줄 강조, 3D 대장장이 애니메이션.
현재 MVP는 2-pass 검사/평가기로 최소 경로를 구현한다.

## 검증 현황과 직접 확인
코드 작성 및 정적 검토만 완료. Unity 컴파일/Play Mode 검증은 미수행이며 통과로 간주하지 않는다.
권장 Game 뷰 1280x720 이상.

1. SampleScene Play → 기본 예제 실행. 자금 88G, 철 9개, 완성품 1개. 판매 후 자금 116G, 완성품 0개.
2. 초기 값에서 시험 실행. 줄별 결과와 예상 12G 표시; 자금100/철10/완성품0 유지. 큐브도 유지.
3. 첫 Material 대입을 지우고 실제 실행. 미선언 변수의 원본 줄 번호 표시, 자금·재고 변화 없음.
4. 각 가장자리를 드래그. 반대쪽 고정과 최소 크기 확인. 긴 코드를 붙여넣고 스크롤/선택/복사 테스트.
5. 2(Blade, 7)의 2/7과 4(Blade, 0)의 4/0, Material = 1의 1을 비교. 여러 자리 12도 전체 토큰으로 판정되는지 확인.
6. 숫자를 호버한 상태에서 입력, 스크롤, 리사이즈 후 숨김 및 새 위치 설명 확인. 미완성 줄 추가 후 다른 줄 숫자 확인.
7. 가열을 5로 바꾸고 실행: 철/가열 소비 후 타격 실패. 시험에서는 동일 실패이나 실제 자원 변화 없음.
8. 실행 버튼 연타로 제작 중복이 없는지, 판매 연타로 완성품 수 이상 판매되지 않는지 확인.

## 알려진 제한
정식 커서 아이콘 대신 가장자리 방향 상자를 사용한다.
런타임 GUI 한국어 글꼴은 OS 글꼴 가용성에 의존한다.
극단적으로 작은 Game 뷰, IME, OS별 클립보드 및 스크롤 후 숫자 위치는 Play Mode 실검증이 필요하다.

## 후속 연결 작업 (2026-11-08)
기존 IMGUI를 재사용. 입력 설정은 activeInputHandler=1 (새 Input System)이며 IMGUI Event로 편집한다.
실행 진입점에 busy 방어를 추가하고 완성품별 제작비를 큐에 보관한다. 판매 시 항목을 먼저 제거해 중복 지급을 방지하고 제작비/판매가/순이익을 표시한다. 숫자 히트가 없는 경우 이전 툴팁을 지운다.
Unity 숨김 배치 실행은 종료 코드 1로 컴파일 전에 종료했다(Logs/MvpCompile.log). Play Mode 및 UI 검증은 미완료다. 기존 에디터에서 Console 오류 확인 후 위 8개 절차로 검증한다.

## 코드 편집 추가 기능
- 코드 입력창에 포커스가 있을 때 Ctrl+Z로 직전 편집을 취소한다. 타이핑/삭제/붙여넣기 등 텍스트 변경 이벤트 단위로 최대 256개를 보관하며 커서, 선택 범위, 스크롤을 복원한다. 실행/판매는 취소 대상이 아니다.
- # 이후는 줄 끝까지 주석. 단독 주석 줄과 명령 뒤 주석을 모두 지원하며 오류 줄 번호는 원본 기준이다. 주석 숫자에는 툴팁을 표시하지 않는다.
- 확인: 7을 8로 수정 후 Ctrl+Z, 여러 줄 붙여넣기 후 Ctrl+Z, 텍스트 선택 삭제 후 Ctrl+Z를 각각 확인한다. 모든 예제 줄 뒤에 # 설명을 추가하고 시험 실행 예상 비용 12G를 확인한다. !Blade 뒤 주석 줄도 허용된다. 주석에 잘못된 구문/숫자를 넣어도 실행에 영향이 없어야 한다.
- 이번 변경은 정적 확인만 수행했으며 Play Mode 키보드/클립보드 실검증은 미수행.

## 작업 공간 이동
빈 바탕에서 왼쪽 마우스 버튼을 누른 채 드래그하면 작업 공간을 이동한다. 코드 창과 오른쪽 결과/판매 패널은 작업 공간 좌표에 고정되며 화면 밖으로 이동할 수 있다. 상단 자원 표시와 원위치 버튼은 화면 고정이다.
3D 카메라는 직교 투영이며 화면 1px당 0.01 월드 단위로 이동해 UI와 제작물의 이동량을 맞춘다. 작업물과 임시 작업대의 월드 좌표는 바꾸지 않는다.
코드 선택/스크롤/버튼/가장자리 크기 조절에서 시작한 드래그는 바탕 이동을 시작하지 않는다. 최소 크기 340x180은 유지하며 화면 경계 제한은 제거했다. 원위치 버튼은 화면 이동량만 초기화하고 코드와 창 크기는 유지한다.
확인 절차: 빈 바탕 드래그 → 코드 창/결과 패널/작업대가 같은 방향과 거리로 이동하는지 확인. 창을 화면 밖으로 보낸 뒤 원위치로 복귀. 이동 후 텍스트 선택, Ctrl+Z, 네 방향 크기 조절, 스크롤 후 숫자 툴팁, 시험/제작/판매 확인. Play Mode 실검증은 아직 미수행.

## 확대/축소와 여러 코드 창
빈 바탕에서 휠 위/아래로 40~200% 확대/축소한다. 마우스가 가리키는 작업 공간 지점을 유지하며 카메라와 UI를 함께 확대한다. 코드 위 휠은 기존 텍스트 스크롤이다.
상단 고정 + 코드 창 생성 버튼은 기본 예제를 담은 독립 창을 현재 화면에 추가한다. 각 창의 코드/스크롤/실행 취소/크기/위치를 별도로 유지한다. 클릭한 창을 활성 편집기로 표시하며 다른 창은 코드 미리보기로 남는다. 실행 결과·재고·판매는 공방 전체 공유이며 동시에 하나만 제작한다.
제목 부분(실행 버튼 제외)을 왼쪽 드래그하면 해당 창만 이동한다. 원위치는 이동량과 확대율을 초기화한다.
검증 절차: 바탕 휠 확대/축소 후 제목 드래그와 가장자리 조절, 숫자 호버를 확인. 새 창 생성 후 서로 다른 코드를 작성하고 창을 번갈아 클릭해 코드/실행취소가 독립인지 확인. 제작 도중 다른 창으로 전환해도 실행 버튼이 잠기는지 확인. Play Mode 실검증 미수행.

## 드래그 및 판매 창 수정
바탕과 코드 제목 드래그는 좌/우 버튼을 모두 지원한다. 시작 버튼을 놓을 때까지 IMGUI hotControl로 드래그를 캡처하고 시작 화면 좌표에서 이동량을 계산한다. 제목 입력 판정은 GUI 확대 행렬 적용 전에 처리한다. 가장자리 리사이즈는 좌클릭을 유지한다.
현재 표시된 활성 창의 판매 패널만 입력을 차단한다. 비활성 창의 보이지 않는 패널 영역과 숨긴 판매 패널 영역은 바탕으로 취급한다. 상단 판매 창 숨기기/열기와 패널 닫기 버튼을 제공한다.
확인: 40/100/200%에서 좌/우 버튼으로 제목을 잡아 창 밖까지 이동 후 놓기. 여러 창이 겹치면 앞 창 선택. 판매 창 숨긴 뒤 같은 영역을 좌/우 드래그해 바탕 이동 확인. 텍스트 선택과 실행 버튼은 제목 이동을 시작하지 않아야 한다. 이번 수정은 정적 검토만 완료, Play Mode 확인은 미수행.

## 코드 창 기본값과 이름 변경
첫 창을 포함해 생성되는 모든 창은 빈 코드로 시작한다(기존 기본 예제 자동 삽입 정책 대체). 생성 순서대로 f1, f2, f3 이름을 부여한다. 이름은 창 표시용이며 도면 언어의 호출 가능한 함수를 정의하지 않는다.
이름을 좌클릭 후 놓으면 이름 편집. Enter 또는 다른 영역 클릭으로 적용, Escape 취소. 빈 이름은 기존 이름 유지, 최대 32자. 제목을 4px 넘게 드래그하면 이름 편집 대신 기존 좌/우 드래그 이동.
확인: 새 Play에서 빈 f1 확인 → 두 창 추가 후 빈 f2/f3 확인 → 이름 클릭/Enter/외부 클릭/Escape 확인 → 변경 후 창 전환 시 이름 유지와 제목 드래그 확인. Play Mode 직접 검증은 미수행.

## 코드 창 시각 조정
코드 글자 18px, 입력 패딩 좌우 각 8px 및 외부 여백 좌우 각 12px. 기본 스크롤바 대신 내부 오른쪽/아래에 6px 단색 스크롤바를 표시한다. 코드 창 배경 alpha 0.78, 카메라 회색 배경 alpha 1 및 SolidColor로 하늘 배경을 숨긴다(제작 오브젝트는 유지). 드래그 감도는 가로 0.8, 세로 1.0으로 조정했다.
Play Mode 확인 필요: 긴 코드 붙여넣기 후 내부 바/휠 스크롤, 숫자 툴팁, 확대 후 제목 이동, 코드 선택을 확인. 이번 변경은 실화면 검증 미수행.

코드 입력부 왼쪽에 빈 줄 번호 여백과 1px 세로 구분선을 추가했다. 활성/비활성 창 모두 동일하게 표시하며 줄 번호는 표시하지 않는다. 입력/스크롤/툴팁은 변경된 viewport 기준으로 계산한다.

코드 입력 GUIStyle을 기본 TextArea 스킨에서 분리해 모든 포커스 상태의 배경/테두리를 제거했다. 여백과 입력부는 하나의 창 배경을 공유한다. 코드 창 클릭 시 해당 창 RGB 밝기를 최대 0.045 올리고 0.25초에 걸쳐 원복한다. 알파는 0.78 유지. 이름 편집에도 테두리 없는 스타일 적용. Play Mode 시각 확인은 미수행.

## 독립 공용 결과/판매 창
결과 판매 창은 작업 공간 좌표 (430,55)의 독립 패널 하나로 분리했다. 코드 창 선택/이동/생성에 따라 위치가 바뀌지 않는다. 패널 제목을 좌/우 드래그해 독립 이동하며 숨긴 상태에는 입력을 받지 않는다. 실행 도면 이름은 실행 시점 스냅샷으로 표시한다. 완성품은 제작비와 제작 도면 이름을 함께 FIFO 보관한다.
모든 코드 창은 공방 busy 잠금을 공유하므로 제작 중 다른 창 시험/제작/판매는 불가하다. 판매는 완성품 하나를 먼저 제거한 뒤 대금을 한 번 지급한다.

## 코드 구문 색상
주석(#부터 줄 끝)은 초록색, 변수명은 흰색, 재료 리터럴은 핑크색, Python 예약어와 반환 기호 !는 주황색, 호출 위치의 숫자 함수명은 연노랑색이다. 재료는 1(재료)의 첫 인자 및 4(작업물, 냉각재료)의 두 번째 인자에서 판정한다. 단독 숫자 대입(a = 1)의 숫자도 핑크색으로 표시한다. 일반 숫자(열 단계)는 흰색이며 재료를 담은 변수도 변수명 색상을 유지한다. match/case/type은 현재 언어에서 일반 변수이므로 흰색이다.

## 완성품 기록과 상점 견적 (2026-11-08)

## 컴파일 오류 창과 상점 분리

컴파일 실패는 상점의 실행 결과/영수증/선택 상품/열림 상태를 변경하지 않는다. 실행 또는 시험 버튼을 누른 코드 창에 원본 줄 번호·원인·검사한 소스를 보관하고, 해당 줄 아래에 빨간 밑줄을 표시한다. 창 상단 전체의 기존 빨간 선은 제거했다. 오류 줄로 자동 스크롤하며 빈 도면은 첫 줄의 짧은 빨간 선, ! 누락은 마지막 유효 명령 줄을 표시한다.

화면 오른쪽 위의 별도 작은 컴파일 오류 창은 도면 이름/줄/원인, 닫기 및 오류 줄 보기 버튼을 제공한다. 작업 공간 확대·이동과 독립적인 화면 좌표를 사용하고, 창 위 클릭/휠이 뒤의 상점·코드 창·바탕으로 전달되지 않도록 차단한다. 코드 창별로 진단을 유지하고 활성 창의 설명만 표시한다. 수정하면 오래된 진단을 지우며 재검사 성공 시에도 해제한다. 설명 창을 닫아도 밑줄은 유지되고, 해당 코드 창을 삭제하면 진단도 함께 사라진다.

Evaluate는 메시지 문자열과 별개로 errorLine/errorMessage/compileError를 반환한다. 실행 중 공정 실패·자원 부족은 기존 제작 결과 기록으로 유지하며 컴파일 오류로 오인하지 않는다.

검증: 런타임 C# 컴파일, 진단5건(원본 줄/CRLF 범위/! 누락/빈 소스/공정 오류 구별) 및 기존 경제14건 통과. Tools > MakeYourItem > Validate Compile Diagnostics로 진단 검사를 재실행할 수 있다. Play Mode UI 직접 확인은 미수행.

직접 확인: SampleScene에서 상점을 숨긴 뒤 기본 도면의 3(Blade)를 3(Missing)으로 바꾸고 ▶ 또는 ▷ → 해당 줄 빨간 밑줄/별도 오류 창/상점 숨김 유지 확인. 긴 코드의 아래쪽에 오류를 넣어 자동 스크롤 확인. 수정 후 표시 해제, 정상 재실행 후 판매 확인. 두 창에서 각각 다른 오류를 내고 전환해 소속 확인. 오류 창 닫기/스크롤 및 뒤쪽 코드·상점 클릭 차단 확인.

## 코드 창 들여쓰기 편집 지원

공백4칸 기준으로 Enter/Tab/Shift+Tab/Backspace를 처리한다. Enter는 현재 줄의 선행 공백을 이어받고, def/333, if/1?, elif/01?, else/0?, while/888, for/123의 블록 헤더가 콜론으로 끝나면4칸을 더한다. 뒤쪽 주석은 무시하며 주석/문자열/딕셔너리의 콜론은 블록으로 취급하지 않는다. 미완성 def(): 입력도 편집 편의상 자동 들여쓰기하지만 실제 실행에는 함수 이름이 필요하다.

Tab은 다음4칸 위치까지 공백을 넣는다. 여러 줄 선택 상태에서는 전체 선택 줄을4칸 들여쓰고, Shift+Tab은 선택 줄 또는 현재 줄의 들여쓰기를 한 단계 줄인다. 다음 줄 시작점까지만 선택한 경우 그 다음 줄은 제외한다. 선행 공백에서 Backspace는 이전4칸 위치까지 지우고, 일반 글자/선택 영역 삭제는 기본 TextArea에 맡긴다. 문자열 내용이나 붙여넣은 소스 전체를 자동 재정렬하지 않는다. 기존 잘못된 들여쓰기의 컴파일 오류 검사는 유지한다.

ForgeMvp.DrawCodeWindow → BlueprintIndentation.Enter/Tab/Backspace → ApplyCodeEdit로 소스와 커서/선택을 함께 갱신한다. 기존 창별 Undo에 한 번의 편집으로 기록되며, 새 줄의 크기를 계산한 뒤 커서 자동 스크롤을 적용한다. Input System의 IME 조합 중 및 조합 변경 프레임에는 사용자 정의 들여쓰기 키 처리를 건너뛰어 기본 입력 처리에 맡긴다.

## print 문자열 출력과 독립 디버그 창

사용 예:

~~~text
print("안녕하세요")
Message = "제작을 시작합니다"
print(Message)
~~~

문자열 인자1개를 받아 디버그 창에 출력하고 None을 반환한다. 작은따옴표/큰따옴표, 빈 문자열, 문자열 변수와 기존 이스케이프를 지원한다. print() / print(1) / print("a", "b")는 인자 오류다. 숫자 별칭은 지정하지 않았으며 기존16개 숫자 대응에 영문 내장 함수print가 추가되어 공통 데이터 항목은17개다. print는 다른 함수와 같은 연노랑색이며 문자열 인자/반환값 설명 툴팁을 제공한다.

출력 전용 코드는 ! 없이 실행할 수 있다. 제작 공정을 포함한 코드의 ! 요구는 유지한다. 컴파일 실패 시 출력은 실행되지 않는다. 실행 중 실패하면 이전 성공 출력만 남는다. 조건·반복·사용자 함수 안에서 실제로 실행된 호출만 출력하고, 실제 제작은 공정 Step 사이의 출력 Step을 순서대로 재생한다. 출력은 비용/재료 소비/공정 애니메이션 지연/상품 생성/난수 시드 소비를 추가하지 않는다. print 전용 실행은 상점 결과를 변경하지 않는다. 시험은 같은 실행기의 출력만 미리 보여주며 실제 재고/자금을 변경하지 않는다.

첫 출력 시 별도 ‘디버그 출력’ 창이 열리며 도면 이름과 시험/실제 실행 구분 뒤에 메시지가 누적된다. 상단 ‘디버그 창’ 버튼으로 다시 열거나 숨길 수 있다. 제목 드래그 이동, 좌우·아래 크기 조절(최소320×160), 내부 스크롤, 새 출력 따라가기, ‘지우기’와 닫기를 제공한다. 이 창은 화면 좌표의 독립 읽기 전용 출력 창이며 작업 공간 확대와 분리된다. 출력 창 위 마우스 입력은 뒤 코드 창/상점/작업 공간에 전달하지 않는다. richText=false이므로 출력 문자열의 <color> 등은 태그로 실행되지 않는다.

안전한 출력 범위: 실행당 최대256회/65536문자이며 초과 호출 줄에서 실행 오류가 난다. 창은 최근256항목/65536문자 이내만 보관하고 오래된 내용을 지운다. 출력 기록은 세션 중에만 유지한다.

주요 파일: BlueprintAliases(Print 등록/서명), BlueprintValidator(문자열 검사/출력 전용 판정), BlueprintRuntime.Call(출력 Step), ForgeMvp.Execute/Craft/DrawDebugWindow/DrawDebugContents(시험·실제 출력과 창), ForgeDebugOutput(누적 버퍼), BlueprintPrintChecks(9개 새 검사).

검증: Unity 참조 및 ENABLE_INPUT_SYSTEM/UNITY_EDITOR C# 컴파일 통과. standalone Mono에서 print9+기존56=65개 검사 통과. 한글/빈 문자열/이스케이프, 함수·조건·반복, 공정 사이 출력 순서, 기존12G 제작비/28G 판매가, 시험 결과 일치, 잘못된 인자, 실패 이전 출력 유지, ! 규칙, 색상/툴팁, 출력 한도/버퍼 지우기를 확인했다. ## 조건·반복문 변수의 실행 시점 검사

변수 읽기를 ‘모든 정적 경로에서 미리 대입되어야 함’ 검사에서 실제 실행 시점 검사로 변경했다. BlueprintValidator.ExprCore는 변수 참조의 타입을 Unknown으로 두어 이전 회차/선택 분기에서 생성되거나 타입이 바뀐 변수를 차단하지 않는다. 문법, 식별자 형식, 함수 존재/인자 수, 리터럴에서 확정할 수 있는 타입, 잘못된 break/return 및 실행 한도 검사는 유지한다.

BlueprintRuntime.Block은 원래부터 if/elif/else와 for/while 본문에 동일한 환경 딕셔너리를 전달한다. 실행된 대입은 다음 회차와 블록 밖에서 보이며, 존재하지 않는 이름을 Eval에서 실제로 읽으면 그 원본 줄에서 ‘변수 '이름'에 아직 값이 없습니다. 이 줄 실행 전에 값을 대입하세요.’ 실행 오류가 발생한다. 실행하지 않은 분기나 단락 평가로 건너뛴 피연산자의 미정의 변수는 오류가 아니다. 반복0회면 새 변수가 생기지 않는다. 함수의 기존 지역 환경과 호출 간 분리는 유지하며 Python 전체 글로벌 이름 탐색을 추가한 것은 아니다.

이전3(Missing) 사례는 이제 컴파일 오류가 아니라 해당 호출 줄의 실행 오류다. 이미 성공한 철 올리기/가열의12G와 철1개는 기존 제작 실패 규칙대로 남고 완성품은 등록되지 않는다. 시험 실행은 여전히 실제 자원을 변경하지 않는다. 컴파일 오류 무소비 회귀 검사는 명백한 잘못된 인자 수3(Blade,1)로 유지하고, 미정의 변수의 실행 중 실패는 별도 회귀 검사로 확인한다.

확인: 사용자가 제공한 a=1 → while(True) → 첫 회차res 생성 → 후속 회차 가열/타격/냉각 → break → !res 도면을 그대로 실행해 철1개/제작비12G/판매가28G/순이익16G 확인. 영문 대응, 분기 밖 사용, for 변수의 블록 밖 사용, 실행하지 않은 분기, 반복0회, 선사용 후대입, None에서 작업물로 재대입, 함수 지역 변수와 호출 격리, 실패 전 비용 유지도 확인했다. Unity 참조 C# 컴파일 및 standalone Mono 변수12+기존65=77개 검사 통과. 실제 Play Mode UI 조작 검증은 미수행이다. Tools > MakeYourItem > Validate Runtime Variables로 새12개 검사를 실행할 수 있다. 결과: Temp/BlueprintVariableChecks.txt.

## 상단 아이콘과 책 안내 UI

우측 상단은 왼쪽부터 기존 디버그 버튼, + 아이콘(코드 창 추가), 상점 아이콘(판매 창 열기/숨기기), 책 아이콘(도면 안내서)으로 구성한다. 아이콘은 ForgeGuideUI.IconButton에서 코드로 그려 이모지 폰트 의존성을 없앴으며 마우스를 올리면 기능 이름을 표시한다. ForgeMvp.DrawToolbar가 기존 코드 창 생성과 상점 표시 상태를 연결한다. 작업 공간 원위치 버튼 및 ResetWorkspaceView 함수는 제거했다. 기존 작업 공간 이동·확대는 유지한다.

책 버튼을 누르면 화면 중앙에 표지·책등·양쪽 빈 페이지로 된 안내서를 연다. 제목 외의 규칙/예문/목차 내용은 아직 작성하지 않았다. × 또는 Esc로 닫는다. 화면 크기에 맞춰 책 크기를 제한하며 작업 공간 확대와 독립적으로 표시한다. 열린 동안 뒤 코드 창·상점·디버그 창으로 마우스/키보드 입력이 전달되지 않도록 기존 모달 입력 차단 경로를 재사용한다. 상단 버튼 영역의 마우스 입력도 뒤 작업 공간과 분리했다.

변경: Assets/Scripts/ForgeMvp.cs, Assets/Scripts/ForgeGuideUI.cs(.meta 포함). 기존 SampleScene 연결을 재사용하고 씬/이미지 파일은 변경하지 않았다. Unity 참조 ENABLE_INPUT_SYSTEM/UNITY_EDITOR C# 컴파일 통과, 원위치 함수/버튼 제거를 확인했다. 이번 변경의 Play Mode 시각·클릭 검증은 미수행이다. 직접 확인: SampleScene Play에서 +로 빈 코드 창 추가, 상점 아이콘 두 번 클릭으로 표시/숨김, 책 아이콘으로 빈 안내서 열기, ×/Esc 닫기, 안내서가 열린 상태에서 뒤 코드 입력/스크롤/창 이동이 차단되는지 확인한다.

## 책 안내서 비모달 창 변경 (2026-11-09)

기존 책 UI의 전체 화면 어두운 배경과 모달 입력 차단을 제거했다. 책을 열어둔 상태에서 코드 입력/실행, 상점, 디버그 창, 작업 공간 조작을 계속할 수 있다. 책과 겹치는 영역의 마우스/휠 입력만 뒤쪽 창에 전달하지 않고, 책을 드래그하는 동안에는 해당 포인터 동작을 책이 캡처한다. 키보드를 전체적으로 차단하지 않는다. 삭제 확인 창의 기존 모달 동작은 유지한다.

기본420×280, 최소280×180의 독립 화면 좌표 창이다. 제목 드래그로 이동하고 좌/우/아래8px 가장자리로 크기를 조절한다. 위쪽 이동은 상단 도구 모음 아래로 제한하고, 수평으로는 제목 일부를 화면에 남긴다. × 또는 상단 책 아이콘으로 닫고 다시 열 수 있으며 세션 내 위치/크기를 유지한다. 전역 Esc 닫기는 제거해 코드 편집 키 입력을 가로채지 않는다. 양쪽 빈 페이지는 창 크기에 맞춰 배치하며 안내 내용은 아직 작성하지 않았다.

변경 파일: ForgeMvp.cs(책 영역만 입력 차단/표시 연결), ForgeGuideUI.cs(창 내부 책 렌더링), ForgeBookWindow.cs(위치/크기/드래그 상태). Unity 참조 ENABLE_INPUT_SYSTEM/UNITY_EDITOR C# 컴파일 통과. Play Mode의 직접 이동/리사이즈/동시 편집 검증은 미수행. 확인 절차: SampleScene Play → 책 열기 → 코드 창 클릭 후 입력·실행 → 책 제목 이동 → 좌우/아래 늘리기·줄이기 → 책 밖 코드/상점 휠 조작 → 책 닫기/재열기 시 위치·크기 유지 확인.

### 세로 크기 조절 커서
코드 창 아래 가장자리8px에 마우스를 올리거나 아래 리사이즈 중이면 실제 커서를 세로 양방향 화살표로 변경한다. 기존 가로 화살표를 전치한32×32 커서를 사용하고 중심 핫스폿을 유지한다. 좌우는 가로, 영역을 벗어나면 기본 커서로 복원한다. 접힌 코드 창과 책/디버그/오류/도구 모음에 가려진 입력 영역은 제외한다. 기존 코드 창 옆의 떠다니는 ↕ 안내 박스는 제거했다. 상점의 아래 리사이즈에도 동일 커서를 적용한다. C# 컴파일 통과, 실제 Play Mode 커서 시각 확인은 미수행.

### 디버그·도면 안내서 크기 조절 커서
디버그 창과 도면 안내서 창의 좌우 가장자리는 가로(↔), 아래는 세로(↕) 커서를 사용한다. 실제 리사이즈와 커서가 같은 가장자리 판정을 사용하며 드래그 중 영역을 벗어나도 방향을 유지한다. 제목 이동과 내부 영역에서는 기본 커서다. Repaint에도 화면상의 창 겹침 순서로 커서를 선택해 뒤 코드 창의 커서가 위 창에 비치거나 입력 이벤트마다 바뀌지 않도록 했다. C# 컴파일 통과, Play Mode 시각 검증은 미수행.
