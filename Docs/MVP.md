# 첫 구현 범위

설계 근거: GameDesign.pdf 2장 플레이 화면, 3장 숫자 언어, 4장 오류 처리, 7장 구현 우선순위.

## 실행
Unity 6000.4.5f1에서 Assets/Scenes/SampleScene.unity를 열고 Play.
씬의 Forge MVP 오브젝트에 ForgeMvp 컴포넌트를 연결했다. 누락 시 SampleScene에서만 런타임 생성하는 보조 경로도 유지한다.
기존 게임 UI가 없는 기본 프로젝트이므로 임시 IMGUI를 사용한다.
코드 편집창, 시험/실제 실행, 콘솔, 판매 버튼과 큐브 작업물을 제공한다.

## 언어와 규칙
영문 대소문자 구분 변수, 0 이상 Int32 정수, 대입/참조, 숫자 함수 1~4, !작업물.
1(1)은 철을 올려 작업물을 반환한다. 반환값 저장 필수.
2(작업물, 열)은 열 단계 1~9와 연료 2G.
3(작업물)은 열 6 이상에서 검날 성형.
4(작업물, 0)은 무료 공기 냉각.
!작업물은 성형 및 열 0을 검사한다. 반환 뒤 명령은 거부한다.
빈 줄은 허용하며 줄 번호를 보존한다. 중첩 호출, 음수와 조건식은 미지원. #부터 해당 줄 끝까지는 주석이며 실행에서 제외한다.
구조/변수/타입 검사를 전체 소스에 먼저 실행하고 별도 상태에서 공정 평가한다.
실제 제작은 평가된 성공 공정을 순서대로 재생한다. 공정 실패 이전 소비는 남는다.
시험은 별도 평가 결과만 표시하며 실제 자금/철/작업물/판매 재고를 변경하지 않는다.
실행 중에는 두 실행 버튼을 잠그며, 입력을 변경해도 시작된 실행 스냅샷은 유지한다.

## 임시 경제
시작 자금 100G, 철 재고 10개. 철 올리기는 철 1개와 가공 비용 10G.
가열 2G, 공기 0G, 기본 검날 판매 28G. 기본 총 비용 12G, 이익 16G.
재고는 이미 보유한 원재료이며 10G는 올리기 시 발생하는 비용으로 임시 정의한다.
공정마다 0.65초 대기. 판매 재고는 누적되고 버튼 1회에 1개 판매.
저장/로드, 철 재구매, 실패 작업물 재개/회수는 미구현.

## 에디터
여러 줄 TextArea의 기본 선택, 복사/붙여넣기와 가로/세로 ScrollView.
네 가장자리 8px 영역에서 크기 조절, 반대편 고정. 최소 340x180 (작은 화면에서는 화면 크기 우선).
창은 작업 공간 좌표에 놓이며 화면 밖으로 이동/확장할 수 있다. 가장자리에는 방향 표시 상자가 나온다.
숫자 전체 토큰의 렌더링 위치를 GUIStyle로 계산한다.
0.5초 호버 후 함수/인자 위치/정수 설명. 입력/스크롤/리사이즈와 포인터 이동은 대기를 재설정한다.
줄별 독립적인 부분 구문 분석이므로 다른 줄이 미완성이어도 툴팁은 동작한다.

## 후속 우선순위
1. 물 담금질의 상태별 경도·수익 비교와 나무 손잡이.
2. 조건문/온도 조회, 상점, 가속, 자동판매.
3. 특수 재료 4~9, 행운/저주/엔딩.
4. 정식 토큰/AST/바이트코드 분리, 실행 줄 강조, 3D 대장장이 애니메이션.
현재 MVP는 2-pass 검사/평가기로 최소 경로를 구현한다.

## 검증 현황과 직접 확인
코드 작성 및 정적 검토만 완료. Unity 컴파일/Play Mode 검증은 미수행이며 통과로 간주하지 않는다.
권장 Game 뷰 1280x720 이상.

1. SampleScene Play → 기본 예제 실행. 자금 88G, 철 9개, 완성품 1개. 판매 후 자금 116G, 완성품 0개.
2. 초기 값에서 시험 실행. 줄별 결과와 예상 12G 표시; 자금100/철10/완성품0 유지. 큐브도 유지.
3. 첫 Material 대입을 지우고 실제 실행. 미선언 변수의 원본 줄 번호 표시, 자금·재고 변화 없음.
4. 각 가장자리를 드래그. 반대쪽 고정과 최소 크기 확인. 긴 코드를 붙여넣고 스크롤/선택/복사 테스트.
5. 2(Blade, 7)의 2/7과 4(Blade, 0)의 4/0, Material = 1의 1을 비교. 여러 자리 12도 전체 토큰으로 판정되는지 확인.
6. 숫자를 호버한 상태에서 입력, 스크롤, 리사이즈 후 숨김 및 새 위치 설명 확인. 미완성 줄 추가 후 다른 줄 숫자 확인.
7. 가열을 5로 바꾸고 실행: 철/가열 소비 후 타격 실패. 시험에서는 동일 실패이나 실제 자원 변화 없음.
8. 실행 버튼 연타로 제작 중복이 없는지, 판매 연타로 완성품 수 이상 판매되지 않는지 확인.

## 알려진 제한
정식 커서 아이콘 대신 가장자리 방향 상자를 사용한다.
런타임 GUI 한국어 글꼴은 OS 글꼴 가용성에 의존한다.
극단적으로 작은 Game 뷰, IME, OS별 클립보드 및 스크롤 후 숫자 위치는 Play Mode 실검증이 필요하다.

## 후속 연결 작업 (2026-11-08)
기존 IMGUI를 재사용. 입력 설정은 activeInputHandler=1 (새 Input System)이며 IMGUI Event로 편집한다.
실행 진입점에 busy 방어를 추가하고 완성품별 제작비를 큐에 보관한다. 판매 시 항목을 먼저 제거해 중복 지급을 방지하고 제작비/판매가/순이익을 표시한다. 숫자 히트가 없는 경우 이전 툴팁을 지운다.
Unity 숨김 배치 실행은 종료 코드 1로 컴파일 전에 종료했다(Logs/MvpCompile.log). Play Mode 및 UI 검증은 미완료다. 기존 에디터에서 Console 오류 확인 후 위 8개 절차로 검증한다.

## 코드 편집 추가 기능
- 코드 입력창에 포커스가 있을 때 Ctrl+Z로 직전 편집을 취소한다. 타이핑/삭제/붙여넣기 등 텍스트 변경 이벤트 단위로 최대 256개를 보관하며 커서, 선택 범위, 스크롤을 복원한다. 실행/판매는 취소 대상이 아니다.
- # 이후는 줄 끝까지 주석. 단독 주석 줄과 명령 뒤 주석을 모두 지원하며 오류 줄 번호는 원본 기준이다. 주석 숫자에는 툴팁을 표시하지 않는다.
- 확인: 7을 8로 수정 후 Ctrl+Z, 여러 줄 붙여넣기 후 Ctrl+Z, 텍스트 선택 삭제 후 Ctrl+Z를 각각 확인한다. 모든 예제 줄 뒤에 # 설명을 추가하고 시험 실행 예상 비용 12G를 확인한다. !Blade 뒤 주석 줄도 허용된다. 주석에 잘못된 구문/숫자를 넣어도 실행에 영향이 없어야 한다.
- 이번 변경은 정적 확인만 수행했으며 Play Mode 키보드/클립보드 실검증은 미수행.

## 작업 공간 이동
빈 바탕에서 왼쪽 마우스 버튼을 누른 채 드래그하면 작업 공간을 이동한다. 코드 창과 오른쪽 결과/판매 패널은 작업 공간 좌표에 고정되며 화면 밖으로 이동할 수 있다. 상단 자원 표시와 원위치 버튼은 화면 고정이다.
3D 카메라는 직교 투영이며 화면 1px당 0.01 월드 단위로 이동해 UI와 제작물의 이동량을 맞춘다. 작업물과 임시 작업대의 월드 좌표는 바꾸지 않는다.
코드 선택/스크롤/버튼/가장자리 크기 조절에서 시작한 드래그는 바탕 이동을 시작하지 않는다. 최소 크기 340x180은 유지하며 화면 경계 제한은 제거했다. 원위치 버튼은 화면 이동량만 초기화하고 코드와 창 크기는 유지한다.
확인 절차: 빈 바탕 드래그 → 코드 창/결과 패널/작업대가 같은 방향과 거리로 이동하는지 확인. 창을 화면 밖으로 보낸 뒤 원위치로 복귀. 이동 후 텍스트 선택, Ctrl+Z, 네 방향 크기 조절, 스크롤 후 숫자 툴팁, 시험/제작/판매 확인. Play Mode 실검증은 아직 미수행.

## 확대/축소와 여러 코드 창
빈 바탕에서 휠 위/아래로 40~200% 확대/축소한다. 마우스가 가리키는 작업 공간 지점을 유지하며 카메라와 UI를 함께 확대한다. 코드 위 휠은 기존 텍스트 스크롤이다.
상단 고정 + 코드 창 생성 버튼은 기본 예제를 담은 독립 창을 현재 화면에 추가한다. 각 창의 코드/스크롤/실행 취소/크기/위치를 별도로 유지한다. 클릭한 창을 활성 편집기로 표시하며 다른 창은 코드 미리보기로 남는다. 실행 결과·재고·판매는 공방 전체 공유이며 동시에 하나만 제작한다.
제목 부분(실행 버튼 제외)을 왼쪽 드래그하면 해당 창만 이동한다. 원위치는 이동량과 확대율을 초기화한다.
검증 절차: 바탕 휠 확대/축소 후 제목 드래그와 가장자리 조절, 숫자 호버를 확인. 새 창 생성 후 서로 다른 코드를 작성하고 창을 번갈아 클릭해 코드/실행취소가 독립인지 확인. 제작 도중 다른 창으로 전환해도 실행 버튼이 잠기는지 확인. Play Mode 실검증 미수행.

## 드래그 및 판매 창 수정
바탕과 코드 제목 드래그는 좌/우 버튼을 모두 지원한다. 시작 버튼을 놓을 때까지 IMGUI hotControl로 드래그를 캡처하고 시작 화면 좌표에서 이동량을 계산한다. 제목 입력 판정은 GUI 확대 행렬 적용 전에 처리한다. 가장자리 리사이즈는 좌클릭을 유지한다.
현재 표시된 활성 창의 판매 패널만 입력을 차단한다. 비활성 창의 보이지 않는 패널 영역과 숨긴 판매 패널 영역은 바탕으로 취급한다. 상단 판매 창 숨기기/열기와 패널 닫기 버튼을 제공한다.
확인: 40/100/200%에서 좌/우 버튼으로 제목을 잡아 창 밖까지 이동 후 놓기. 여러 창이 겹치면 앞 창 선택. 판매 창 숨긴 뒤 같은 영역을 좌/우 드래그해 바탕 이동 확인. 텍스트 선택과 실행 버튼은 제목 이동을 시작하지 않아야 한다. 이번 수정은 정적 검토만 완료, Play Mode 확인은 미수행.

## 코드 창 기본값과 이름 변경
첫 창을 포함해 생성되는 모든 창은 빈 코드로 시작한다(기존 기본 예제 자동 삽입 정책 대체). 생성 순서대로 f1, f2, f3 이름을 부여한다. 이름은 창 표시용이며 도면 언어의 호출 가능한 함수를 정의하지 않는다.
이름을 좌클릭 후 놓으면 이름 편집. Enter 또는 다른 영역 클릭으로 적용, Escape 취소. 빈 이름은 기존 이름 유지, 최대 32자. 제목을 4px 넘게 드래그하면 이름 편집 대신 기존 좌/우 드래그 이동.
확인: 새 Play에서 빈 f1 확인 → 두 창 추가 후 빈 f2/f3 확인 → 이름 클릭/Enter/외부 클릭/Escape 확인 → 변경 후 창 전환 시 이름 유지와 제목 드래그 확인. Play Mode 직접 검증은 미수행.

## 코드 창 시각 조정
코드 글자 18px, 입력 패딩 좌우 각 8px 및 외부 여백 좌우 각 12px. 기본 스크롤바 대신 내부 오른쪽/아래에 6px 단색 스크롤바를 표시한다. 코드 창 배경 alpha 0.78, 카메라 회색 배경 alpha 1 및 SolidColor로 하늘 배경을 숨긴다(제작 오브젝트는 유지). 드래그 감도는 가로 0.8, 세로 1.0으로 조정했다.
Play Mode 확인 필요: 긴 코드 붙여넣기 후 내부 바/휠 스크롤, 숫자 툴팁, 확대 후 제목 이동, 코드 선택을 확인. 이번 변경은 실화면 검증 미수행.

코드 입력부 왼쪽에 빈 줄 번호 여백과 1px 세로 구분선을 추가했다. 활성/비활성 창 모두 동일하게 표시하며 줄 번호는 표시하지 않는다. 입력/스크롤/툴팁은 변경된 viewport 기준으로 계산한다.

코드 입력 GUIStyle을 기본 TextArea 스킨에서 분리해 모든 포커스 상태의 배경/테두리를 제거했다. 여백과 입력부는 하나의 창 배경을 공유한다. 코드 창 클릭 시 해당 창 RGB 밝기를 최대 0.045 올리고 0.25초에 걸쳐 원복한다. 알파는 0.78 유지. 이름 편집에도 테두리 없는 스타일 적용. Play Mode 시각 확인은 미수행.

## 독립 공용 결과/판매 창
결과 판매 창은 작업 공간 좌표 (430,55)의 독립 패널 하나로 분리했다. 코드 창 선택/이동/생성에 따라 위치가 바뀌지 않는다. 패널 제목을 좌/우 드래그해 독립 이동하며 숨긴 상태에는 입력을 받지 않는다. 실행 도면 이름은 실행 시점 스냅샷으로 표시한다. 완성품은 제작비와 제작 도면 이름을 함께 FIFO 보관한다.
모든 코드 창은 공방 busy 잠금을 공유하므로 제작 중 다른 창 시험/제작/판매는 불가하다. 판매는 완성품 하나를 먼저 제거한 뒤 대금을 한 번 지급한다.
